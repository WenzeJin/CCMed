# CCTester Project Analysis & Core Technical Philosophy

## 1. Project Overview (Functionality & Design)

**CCTester** is an automated testing framework designed to verify logical evaluation systems (such as rule engines, model checkers, or complex business logic components).

### Core Functionality
*   **Goal**: Verify the correctness of a System Under Test (SUT) when processing complex logical formulas.
*   **Workflow**:
    1.  **Source Case Generation**: Generates a large number of basic test cases (Source Cases) based on predefined XML rule templates by combining different data patterns (Patterns) and boolean functions (Bfuncs).
    2.  **Source Execution**: Executes these basic cases on the SUT to obtain their "baseline truth" (e.g., whether the formula evaluates to True or False under current data).
    3.  **Metamorphic Testing**: Uses the results of the basic cases to construct more complex "Follow-up Cases" via logical operators (AND, OR, IMPLIES, FORALL, EXISTS, etc.).
        *   *Example*: If Case A is True and Case B is False, the new case `A AND B` must be False.
    4.  **Verification**: Executes the follow-up cases and checks if the SUT's output matches the logically derived expected result. Discrepancies are reported as bugs.

### System Design
The project follows a modular and layered architecture:
*   **Core Control Layer (`com.wenzejin.core`)**: `Core` coordinates the workflow, `Config` manages settings, and `Preprocessor` handles rule parsing and source case generation (supporting both Enum and Random strategies).
*   **Data Model Layer (`com.wenzejin.core.rule`, `com.wenzejin.core.cases`)**: `Rule`/`Formula` defines the Abstract Syntax Tree (AST) of logical formulas. `TestCase` encapsulates specific testing scenarios.
*   **Execution Abstraction Layer (`com.wenzejin.core.worker`, `com.wenzejin.core.TestExecutor`)**: `TestWorker` interfaces with the SUT, allowing easy adaptation to different systems. `TestExecutor` manages concurrent execution.
*   **Algorithmic Strategy Layer (`com.wenzejin.core.mr`)**: `ARTCore` (Adaptive Random Testing) and `RandomCore` implement strategies for synthesizing follow-up cases.

### Core Philosophy
*   **Logic-Based Metamorphic Testing**: Uses logical consistency as the test oracle rather than predefined outputs.
*   **Combinatorial Testing**: Emphasizes coverage of data patterns and boolean function truth tables.
*   **Adaptive Strategy**: Uses ART to intelligently explore the testing space based on previous results.

## 2. Proposed Academic Terminology

To better articulate the unique contribution of this work for academic publication (e.g., ICSE, FSE, ASE), the following terminology is proposed.

### Core Technical Philosophy Name
**English**: Semantic-Guided Constructive Metamorphism (SGCM)
**Chinese**: 语义制导的构造式蜕变

### Key Concept Replacement
*   **Component / FormulaWithTag** $\rightarrow$ **Semantic Primitive (语义原语)**
    *   *Definition*: The atomic unit of logic carrying semantic information derived from SUT execution, used to construct complex formulas.
*   **Alternative**: **Verified Logic Fragment (已验证逻辑片段)**

### Technical Philosophy Elaboration

#### English Version
**Abstract:**
Unlike traditional Metamorphic Testing (MT), which typically relies on morphing a single source input into a follow-up input ($Input_A \xrightarrow{mutation} Input_B$), **SGCM** adopts a bottom-up, constructive approach ($Component_A + Component_B \xrightarrow{logic} Input_{New}$). The core philosophy treats source test cases not merely as tests, but as generators of **Semantic Primitives**.

**Key Mechanisms:**
1.  **Semantic Extraction (Decomposition):** The system executes source test cases to extract logic fragments (formulas). Crucially, the execution results (e.g., truth values, variable linkages) are captured as **Semantic Tags**. These tags transform a static formula into a dynamic **Semantic Primitive**.
2.  **Semantic Flow & Preservation:** These primitives are decoupled from their original test context. Their semantic information (the Tags) "flows" into a shared pool, preserving the behavioral state of the System Under Test (SUT) for that specific logic fragment.
3.  **Constructive Synthesis:** Follow-up test cases are not generated by mutating inputs, but by **synthesizing** complex logic structures using these Semantic Primitives. The expected behavior (Oracle) of the new complex case is logically derived from the preserved tags of its constituent primitives.

**Significance:**
This approach ensures that the complexity of test cases grows organically while maintaining strict logical consistency. It effectively turns the SUT's own behavior against itself to detect deep logic flaws.

#### Chinese Version
**摘要：**
与传统的蜕变测试（Metamorphic Testing, MT）通常依赖于将单个源输入“变异”为后续输入不同，**SGCM** 采用了一种自底向上的“构造式”方法。该思想的核心在于，不将源测试用例仅仅视为测试任务，而是将其视为**语义原语（Semantic Primitives）**的生成器。

**关键机制：**
1.  **语义提取（分解）：** 系统执行源测试用例以提取逻辑片段（Formulas）。关键在于，执行结果（如真值、变量链接关系）被捕获并封装为**语义标签（Semantic Tags）**。这些标签将静态的公式转化为动态的**语义原语**。
2.  **语义流动与保持：** 这些原语从原始测试上下文中解耦。它们的语义信息（标签）“流动”并汇聚到一个共享池中，持久化地保存了被测系统（SUT）针对该特定逻辑片段的行为状态。
3.  **构造式合成：** 后续测试用例并非通过修改输入生成，而是通过**合成**（Synthesizing）这些语义原语来构建更复杂的逻辑结构。新的复杂用例的预期行为（Oracle），是基于其组成原语所携带的标签，通过严格的逻辑运算推导得出的。

**意义：**
这种方法确保了测试用例的复杂度能够有机增长，同时保持严格的逻辑一致性。它有效地利用系统自身的行为特征来反向构建高复杂度的测试场景，从而检测深层的逻辑缺陷。

### Why this name?
1.  **Semantic-Guided**: Highlights the use of `Tags` (execution results/semantics) to guide generation, distinguishing it from blind random combination.
2.  **Constructive**: Differentiates from traditional mutation-based MT. It emphasizes building up complexity ($A + B \to C$).
3.  **Metamorphism**: Roots the work in the MT domain (using relations rather than absolute truth as oracles).
